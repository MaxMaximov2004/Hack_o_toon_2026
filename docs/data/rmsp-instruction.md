# Инструкция: выгрузка реестра МСП и подготовка файла для ETL

**Кто делает:** Python-разработчик (выгрузить может любой участник с браузером).
**Сколько времени:** 30–60 минут, если сайт отдаёт выгрузку без лимитов; дольше, если придётся резать на части.
**Что получится:** `etl/data/rmsp_61.csv.gz` и отчёт `etl/data/rmsp_61_report.md` в репозитории. ETL загрузит
файл в `etl.raw_rmsp`, а из него — в `core.company`.

## Зачем

По словам куратора:

- **таблица кейса (лист МОД1, 759 строк) — это только НАШИ клиенты;**
- **все остальные («не наши») берутся из реестра МСП ФНС** — https://rmsp.nalog.ru/search.html?mode=extended,
  регион «Ростовская область»;
- **среди наших клиентов есть закрывшиеся и исключённые из реестра.** В самом файле кейса колонка
  «Дата исключения из реестра» пустая у всех 759, поэтому исключённых находим сверкой со свежей выгрузкой.

Итоговые статусы компании:

| Есть в таблице кейса | Есть среди действующих в реестре | Статус в системе | Цвет на карте |
| --- | --- | --- | --- |
| да | да | действующий клиент (`is_client = true`, `status = active`) | фиолетовый |
| да | нет | клиент исключён из реестра (`is_client = true`, `status = excluded`) | серый, по умолчанию скрыт |
| нет | да | потенциальный клиент (`is_client = false`, `status = active`) | оранжевый |

«Исключён из реестра МСП» — не всегда «закрылся»: компания могла вырасти из МСП или не сдать отчётность. В
интерфейсе пишем «исключён из реестра МСП», а не «закрыт».

## Шаг 1. Выгрузить действующие компании

1. Открыть https://rmsp.nalog.ru/search.html?mode=extended.
2. В расширенном поиске выбрать **Регион: 61 — Ростовская область**. Остальные фильтры не трогать.
3. Найти и **записать общее число найденных** — понадобится для проверки.
4. Выгрузить результат (кнопка выгрузки/скачивания в результатах поиска; файл будет с теми же колонками, что
   таблица кейса — она выгружена оттуда же).
5. **Если сайт отдаёт не всё** (в файле меньше строк, чем найдено, или есть ограничение на выгрузку) — резать
   запрос на части, пока каждая не влезает в лимит, и выгружать по очереди:
   - сначала по **виду субъекта**: юрлица / ИП;
   - потом по **категории**: микро / малые / средние;
   - если всё ещё много — по **районам и городам** области.
   Сумма строк по частям должна сойтись с общим числом из п. 3. Пересечения частей не страшны — скрипт уберёт дубли.
6. Сохранить файлы **как есть, не открывая в Excel**, в папку `data-raw/rmsp/active/`, имена с датой:
   `rmsp61_2026-10-23_ul.xlsx`, `rmsp61_2026-10-23_ip_micro.xlsx` и т. п.

> Почему не открывать в Excel: при пересохранении он превращает ИНН в число и теряет ведущий ноль
> (`0265052371` → `265052371`), а даты — в свой формат. Скрипт умеет чинить ИНН, но лучше не давать повода.

## Шаг 2. Выгрузить исключённых (если форма позволяет)

Если в расширенном поиске можно искать субъектов, исключённых из реестра (обычно — по дате исключения):

1. Регион 61, исключённые, период исключения — с 01.01.2016 (самая ранняя дата включения у наших клиентов — 2016 год).
2. Выгрузить так же, сохранить в `data-raw/rmsp/excluded/`.

Это даёт дату исключения по клиентам. Если такого режима нет — шаг пропускаем: клиент, которого нет среди
действующих, всё равно получит статус «исключён», просто без даты.

## Шаг 3. Подготовить файл скриптом

Из корня репозитория (нужен только `openpyxl`: `pip install openpyxl`):

```bash
python3 tools/rmsp/prepare_rmsp.py \
  --active   data-raw/rmsp/active/* \
  --excluded data-raw/rmsp/excluded/* \
  --clients  infra/db/tools/case.xlsx \
  --out      etl/data/rmsp_61.csv.gz
```

`--excluded` можно не указывать, если шага 2 не было. Скрипт:

- принимает `.xlsx` и `.csv` (UTF-8 или Windows-1251, разделитель `;` или `,`), сам находит строку заголовка;
- сопоставляет колонки по названиям, предупреждает, если какой-то нет;
- чинит ИНН с потерянным ведущим нулём (юрлицо — 10 цифр, ИП — 12);
- отбрасывает строки не из Ростовской области;
- убирает дубли по ИНН (действующая запись важнее исключённой);
- пишет `rmsp_61.csv.gz` и отчёт `rmsp_61_report.md`.

## Шаг 4. Проверить отчёт — до коммита

Открыть `etl/data/rmsp_61_report.md` и пройти по списку:

- [ ] «Действующих» ≈ общему числу найденных на сайте из шага 1. Расхождение больше нескольких строк — какая-то часть не выгрузилась.
- [ ] «Не Ростовская обл. (отброшено)» = 0 или почти 0. Много — где-то не выставлен фильтр региона.
- [ ] «Найдены среди действующих» — большая часть из 759 клиентов. Если найдено подозрительно мало (меньше половины) —
      скорее всего, сломаны ИНН или выгружено не всё.
- [ ] «Не найдены нигде» + «найдены среди исключённых» = кандидаты в исключённые клиенты. **Это число — на слайд
      «Экономика»**: «N из 759 клиентов в CRM уже исключены из реестра МСП — радар находит их автоматически».
- [ ] Раздел «Предупреждения» пуст (или понятно, почему нет колонки).

## Шаг 5. Закоммитить и пересобрать

```bash
git add etl/data/rmsp_61.csv.gz etl/data/rmsp_61_report.md
git commit -m "data: выгрузка реестра МСП, Ростовская обл., <дата>"
```

- Сырые файлы `data-raw/` в git не кладём (они в `.gitignore`), кладём только `.csv.gz` и отчёт.
- Если `.csv.gz` больше 50 МБ — сказать техлиду (Git LFS или выложить файл отдельно и скачивать в Dockerfile).
- Проверить, что ETL подхватил данные:
  ```bash
  docker compose build etl && docker compose run --rm etl
  docker compose exec postgres psql -U postgres -d radar -c \
    "select is_client, status, count(*) from core.company group by 1, 2 order by 1, 2"
  ```
  Ожидаемо три группы: клиенты действующие, клиенты исключённые, не клиенты.

## Как ETL использует файл

1. `TRUNCATE etl.raw_rmsp`, затем `COPY etl.raw_rmsp FROM STDIN WITH (FORMAT csv, HEADER true)` из распакованного файла.
2. Множество ИНН клиентов — из `etl.raw_clients` (сид из таблицы кейса).
3. В `core.company` попадает объединение: все действующие из реестра + все клиенты из кейса.
   Для клиента данные берутся из реестра, если он там есть (они свежее), иначе — из таблицы кейса.
4. Статусы — по таблице в начале этой инструкции.

## Обновить данные позже

Повторить шаги 1–5 с новой датой в именах файлов. Отчёт перезапишется, старая версия останется в истории git.

## Частые проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «не нашёл строку заголовка с колонкой ИНН» | выгрузка в другом формате или пустая | открыть файл на просмотр (без сохранения), проверить, что в заголовке есть «ИНН» |
| «нет колонок …» в предупреждениях | сайт поменял названия колонок | поправить список `COLUMNS` в `tools/rmsp/prepare_rmsp.py` |
| много «ИНН с потерянным ведущим нулём» | файл пересохраняли в Excel | скачать заново, не открывая в Excel |
| клиентов найдено мало | неполная выгрузка или чужой регион | сверить число строк с сайтом, проверить фильтр региона |
| ETL падает на COPY | файл не из скрипта или битый gzip | пересоздать скриптом, не редактировать руками |
