# 13. Тестирование модулей 1 и 2 — Claude Code ходит по сайту сам

**Цель:** проверить модули 1 «Радар» и 2 «Навигатор» на **соответствие ТЗ и кейсу** и на **правильность данных и
логики**: каждая цифра на экране сверяется с базой и API. Код не правим — только находим и описываем баги.
**Как:** у каждого тестировщика Claude Code управляет браузером через Playwright MCP (кликает, вводит, делает
скриншоты), а цифры проверяет запросами к БД и API. Человек ставит задачу, смотрит за ходом и решает спорные случаи.

**Источники правды** (при расхождении экрана с ними — это баг): кейс (`Case.pdf`: критерии жюри, требования),
[00-common](00-common.md) (контракт, демо-сценарий модуля 1), [01-frontend](01-frontend.md),
[07](07-star-actual-location.md) («Где работает»), [08](08-product2-contract.md) (контракт модуля 2),
[11](11-frontend-navigator.md) и [12](12-frontend-todo.md) (экран Навигатора), `contracts/examples/`.

## 1. Подготовка (оба, ~20 минут)

```bash
git pull
docker compose --profile product2 down -v                 # чистая база — эталонные цифры ниже для неё
docker compose --profile product2 up -d --build
bash infra/smoke.sh                                        # должно быть «ВСЁ ЗЕЛЁНОЕ»; иначе — сначала техлиду
git log --oneline -1                                       # записать хэш — он идёт в каждый отчёт
```

**Playwright MCP для Claude Code** (один раз):

```bash
npx playwright install firefox                          # Chrome берётся установленный в системе
claude mcp add playwright        -- npx @playwright/mcp@latest                         # Google Chrome
claude mcp add playwright-ff     -- npx @playwright/mcp@latest --browser firefox
claude mcp add playwright-phone  -- npx @playwright/mcp@latest --device "iPhone 15"     # мобильный вид в Chrome
```

Перезапустить Claude Code → в `/mcp` три сервера `connected` (если какой-то не поднялся — `npx @playwright/mcp@latest --help`
покажет актуальные флаги). Яндекс.Браузер — на движке Chromium, автотесты в Chrome его покрывают, а **финальный
проход — вручную в настоящем Яндекс.Браузере и на реальном телефоне** (см. п. 5).

**Вход:**

| | Логин | Код 2FA |
| --- | --- | --- |
| Менеджер | `demo@rt.ru` / `Demo2026!` | `python tools/qa/totp.py` |
| Админ | `admin@rt.ru` / `Admin2026!` | первый вход — QR (это тоже проверка); дальше `python tools/qa/totp.py --admin` |

Код живёт 30 с — получать прямо перед вводом.

## 2. Как проверять данные — оракулы

Цифры на экране сверяются с БД (суперпользователь, только чтение) и с API:

```bash
docker exec radar-postgres psql -U postgres -d radar -c "<SQL>"      # БД
curl -s -H "Authorization: Bearer <токен>" "http://localhost/api/..."  # API; токен — из DevTools → sessionStorage
```

**Эталон на чистой базе** (после `down -v`; если отличается — сначала выяснить почему):

| Что | Значение | SQL |
| --- | --- | --- |
| Компаний на карте области (по умолчанию) | 187 986 | `select count(*) from core.company where status='active'` |
| «Не наши» | 187 236 | `… where status='active' and not is_client` |
| Клиенты: действующих / исключённых | 750 / 9 | `select status, count(*) from core.company where is_client group by 1` |
| «Логистика, выручка 10–100 млн» — все / «не наши» | 1 667 / 1 654 | `… and industry='logistics' and revenue_est between 1e7 and 1e8` |
| Белые пятна (общая карта) | 3: Целинский р-н, Багаевский р-н, г. Донецк | `select m.name, s.reason from core.municipality_stats s join core.municipality m on m.id=s.municipality_id where industry='all' and is_white_spot` |
| Инвестпроектов / стадии | 63: проектирование 8, строительство 34, запуск 21 | `select stage, count(*) from core.invest_project group by 1` |
| Проект с инициатором в реестре | №31 «…порт…» → «АО "Ростовский порт"» | `GET /api/projects/31/related-companies` |

**Правило:** любая цифра в интерфейсе (счётчики, «Найдено: N», числа в кластерах, суммы, проценты) должна совпасть
с оракулом **при тех же фильтрах**. Не совпало — баг с обеими цифрами в отчёте.

## 3. Тестировщик А — модуль 1 «Радар»

| ID | Что проверить | Ожидается (оракул) |
| --- | --- | --- |
| **Р1** Вход | неверный пароль; верный → 2FA; неверный код; 5 неверных кодов; верный код; «Выйти»; открыть `/` без входа; `/login?next=…` после входа | «Неверный email или пароль»; «Неверный код» и поле очищено; после 5-го — «Слишком много попыток» и на `/login`; выход стирает сессию; без входа → `/login`; после входа — возврат на `next`. Админ: при первом входе QR |
| **Р2** Карта области | стартовый вид; кластеры; клик по кластеру; приближение к Азову до точек; клик по точке | центр Ростовской обл., зум 7, вся область; сумма чисел кластеров = 187 986; клик → приближение +2; при ≤ 1500 компаний в окне — точки цветом `kind`; точка → карточка |
| **Р3** Наши / Не наши / Все | переключатель; цвета; легенда | `ours` фиолетовый, `others` оранжевый, `excluded` серый; итоги = оракулы 750 / 187 236 / 187 986; легенда видна всегда |
| **Р4** Фильтры = URL | демо: «Логистика» + выручка 10–100 млн; затем каждый фильтр по одному (отрасль, район, категория, рост, «новые», поиск); «Сбросить»; скопировать URL в новую вкладку | после демо-фильтра «Найдено» = 1 667 (с «Не наши» — 1 654), карта и список меняются **вместе**; URL содержит фильтр, повтор `industry=…&industry=…`; новая вкладка открывает то же; неверное значение в URL → понятная ошибка, не белый экран |
| **Р5** Список ⇄ карта | приблизить карту → список; сортировки; пагинация; пустой результат | список — только компании в окне карты (`minLat…` в запросе), «Найдено» = `total` API; сортировка по выручке — пустые в конце; пусто → «В этой области ничего нет…» |
| **Р6** Карточка компании | открыть 3 компании: клиент, «не наш», исключённая | поля = `GET /api/companies/{id}` и строка в БД; ИНН копируется; бейдж «оценка» при модельной выручке, источник «ФНС»/«оценка»; «исключён из реестра МСП», не «закрылся» |
| **Р7** Белые пятна и потенциал | слой «Белые пятна»; подсказка; панель района | ровно 3 района из оракула; в подсказке — текст `reason` («1157 компаний, охват РТ 0.00%…»); цифры панели района = `/api/municipalities/stats` |
| **Р8** Исключённые | «Показать исключённых»; пресет «Исключённые клиенты»; цифра для слайда | серые точки; пресет = `client=ours&status=excluded`, «Найдено» 9; надпись «9 из 759 клиентов исключены из реестра» |
| **Р9** Экспорт | «CSV» и «В CRM» при демо-фильтре; без фильтра; подтверждение «Будет выгружено N» | файл скачался, имя `radar_ГГГГ-ММ-ДД.csv` / `radar_bitrix_…`; **строк в файле = «Найдено»** (1 667); UTF-8 с BOM, `;`, 17 колонок (CSV) / 7 (Bitrix); без фильтра — «Слишком много, сузьте фильтр (187 986 компаний)», не «внутренняя ошибка». Открыть файл (Python `csv`) и сверить 3 случайных строки с БД |

**Хвосты модуля 1** — проверять, **если уже есть на экране** (иначе отметить «не реализовано», это не баг тестирования):
импорт клиентов админом (CSV ИНН Целинского р-на → пятно исчезает без перезагрузки; менеджеру кнопки нет),
«Где работает» в карточке (сценарий «Сальск → Азов» из `07`, фильтр «Работает не там, где зарегистрирован», пунктир).

## 6. Формат бага

```markdown
### RADAR-07 [критичный] Экспорт: строк в файле меньше, чем в списке
- **Коммит:** 158606f · **Где:** Chromium 1440×900 · **Экран:** Радар, фильтр «Логистика, 10–100 млн»
- **Шаги:** 1) … 2) … 3) «В CRM»
- **Ожидалось:** 1 667 строк (= «Найдено», SQL: `…`)
- **Получилось:** 1 500 строк
- **Доказательства:** `docs/qa/shots/radar-07.png`, ответ API / SQL
- **Предположительно чей:** фронт / core-api / export / ETL — по признакам (решает техлид)
```

Важность: **критичный** — ломает демо-сценарий или неверные данные; **важный** — расходится с ТЗ или кейсом, есть
обход; **мелкий** — вид, тексты. Скриншоты — `docs/qa/shots/`. В конце файла — сводка: проверено / пройдено / багов
по важности / «не реализовано».

## 8. После тестирования

1. Каждый пушит свой `docs/qa/bugs-*.md` и `docs/qa/shots/` (только эти файлы).
2. Техлид разбирает баги → владельцам (фронт, Java, C#, Python), критичные — первыми.
3. После исправлений — **регрессия**: `bash infra/smoke.sh` + повтор упавших блоков тем же промптом, затем раздел 5.
4. Зелёная регрессия → тег `p2-build-N`. С этого момента разработка модуля 3 идёт поверх проверенной точки,
   и смоук гоняется после каждого его пуша.
