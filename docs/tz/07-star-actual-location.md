# 07. Задача со звёздочкой — «зарегистрирован в одном месте, работает в другом»

**Когда:** после зелёной сборки продукта 1, параллельно с продуктом 2 — кто освободился.
**Кто:** Java #2 (эндпоинты), фронт (карточка и карта), Python (источник данных, по возможности).

## Задача куратора (дословно по смыслу)

Найти ИНН, которые зарегистрированы в одном месте, а бизнес ведут в другом — внутри области и между областями.
Пример: ИП зарегистрирован по домашнему адресу в Сальске, а офис — в Азове. Сам куратор готового решения не знает.

## Почему это нельзя просто «посчитать» из реестра

В реестре МСП только адрес регистрации (у ИП — прописка). Фактического адреса в открытых данных ФНС нет.
Значит, решение — **собирать фактические места из нескольких источников** и хранить их рядом с адресом регистрации,
с указанием источника и уверенности. Честно говорим это на защите — и показываем механизм.

## Источники фактического адреса

| Источник | Кого покрывает | Как получить | В прототипе |
| --- | --- | --- | --- |
| Адреса точек подключения услуг Ростелекома (биллинг/CRM) | наших клиентов — самый точный источник | выгрузка из CRM → CSV | **да**: импорт CSV |
| Менеджеры по продажам | любых, кого обзвонили/посетили | ввод в карточке компании | **да**: форма в карточке |
| ЕГРЮЛ: обособленные подразделения юрлиц | юрлица с филиалами | выписка по ИНН (egrul.nalog.ru) | по возможности, для десятков компаний (Python, проверить доступность) |
| Госзакупки (44-ФЗ, 223-ФЗ) | поставщики госзаказчиков | место поставки в контрактах (открытые данные ЕИС) | нет, план развития |
| Онлайн-карты и справочники организаций | розница, услуги, общепит | поиск по названию и городу, API с ключом | нет, план развития |
| Лицензии | алкоголь, медицина, образование и т. п. | адреса мест деятельности в реестрах лицензий | нет, план развития |

## Модель данных (уже в БД)

`core.company_location` — несколько мест на компанию:

| Поле | Смысл |
| --- | --- |
| `inn` | компания — **по ИНН, без внешнего ключа**: ETL пересоздаёт `company`, а введённые людьми адреса должны пережить перезагрузку |
| `kind` | `registered` / `actual` (регистрацию берём из `company`, в таблицу пишем только `actual`) |
| `municipality_name` | район/город области в нормализованном виде (`Азовский р-н`, `г. Азов`) или NULL |
| `region_name` | если место за пределами области (`Краснодарский край`) |
| `address`, `lat`, `lon` | что известно |
| `source` | `crm`, `manager`, `egrul`, … |
| `confidence` | 0..1: `crm` 0.9, `manager` 0.8, `egrul` 0.7 |
| `note` | комментарий менеджера |

«Перемещённая» компания = есть `actual` с `municipality_name`, отличным от района регистрации, или с `region_name` другого региона.

## Эндпоинты (Java #2, пакет `locations/`)

| Метод и путь | Что делает |
| --- | --- |
| `GET /api/companies/{id}/locations` | место регистрации (из `company`) + все фактические места из `company_location` по ИНН |
| `POST /api/companies/{id}/locations` | `{ municipalityName? , regionName?, address?, note? }` → `source = 'manager'`, `confidence = 0.8`, 201 |
| `DELETE /api/companies/{id}/locations/{locationId}` | удалить своё (или любое — роль `admin`) |
| `POST /api/locations/import` | CSV `inn;municipality;region;address;source` → `{ rows, matched, notFound }`, роль `admin` |

```json
// GET /api/companies/101/locations
{
  "registered": { "municipalityName": "Сальский р-н", "settlement": "г. Сальск", "lat": 46.47, "lon": 41.54 },
  "actual": [ { "id": 7, "municipalityName": "г. Азов", "regionName": null, "address": "ул. Ленина, 1",
                "lat": 47.11, "lon": 39.42, "source": "manager", "confidence": 0.8,
                "note": "офис и склад, со слов директора", "createdAt": "2026-10-24T10:12:00Z" } ],
  "relocated": true
}
```

**Логика:**

- `municipalityName` проверять по справочнику `municipality` (как в `/api/dictionaries`) — иначе 400; координаты, если не
  переданы, — центроид этого муниципалитета.
- В `CompanyFilter` добавить `relocated=true` →
  `EXISTS (SELECT 1 FROM company_location l JOIN municipality m ON m.id = c.municipality_id WHERE l.inn = c.inn AND l.kind = 'actual' AND (l.region_name IS NOT NULL OR l.municipality_name <> m.name))`.
- В `CompanyShort` — поле `relocated` (boolean), чтобы показать значок в списке.

## Интерфейс (фронт)

- Карточка компании: блок «Где работает» — регистрация и фактические места с источником и уверенностью; кнопка
  «Указать фактическое место» (выбор района/города из справочника или «другой регион», адрес, комментарий).
- Список: значок «работает в другом месте» у `relocated`.
- Фильтр: флажок «Работает не там, где зарегистрирован» (`relocated=true`).
- Карта: у выбранной компании — пунктир от точки регистрации к фактической.

## Данные для демо

**Не выдумывать** перемещённые компании пачкой. На демо:

1. Открываем ИП, зарегистрированного в Сальске, → «Указать фактическое место» → г. Азов → компания появляется в фильтре
   «работает не там, где зарегистрирован», на карте — пунктир Сальск → Азов.
2. Импорт CSV «адреса точек подключения из CRM» (демо-файл с несколькими строками, явно подписанный как пример формата).
3. Если Python успел — несколько реальных юрлиц с обособленными подразделениями из ЕГРЮЛ (источник `egrul`).

## Что сказать на защите

«Фактического адреса нет ни в одном открытом реестре, поэтому мы сделали механизм, который собирает его из нескольких
источников с оценкой достоверности. Самый ценный источник уже есть у Ростелекома — адреса точек подключения в биллинге: они
сразу покажут, где на самом деле работают все текущие клиенты. Дальше подключаются менеджеры, ЕГРЮЛ, госзакупки и справочники
организаций».

## Готово, когда

Сценарий «Сальск → Азов» проходит вживую: ввод в карточке → фильтр → пунктир на карте; импорт CSV работает; перезапуск
ETL не стирает введённые адреса.
