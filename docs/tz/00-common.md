## Данные — что есть на самом деле (ответ куратора)

| Источник | Что это | Где лежит |
| --- | --- | --- |
| Таблица кейса, лист МОД1 (759 строк) | **НАШИ клиенты** Ростелекома. Среди них есть закрывшиеся и исключённые из реестра; колонка «Дата исключения» в файле пустая у всех | сид → `etl.raw_clients` |
| Реестр МСП ФНС, rmsp.nalog.ru, Ростовская обл. | **весь рынок** → всё, чего нет среди наших, — «не наши» (потенциальные) | выгрузка → `etl/data/rmsp_61.csv.gz` → `etl.raw_rmsp` ([инструкция](../data/rmsp-instruction.md)) |
| Открытые данные ФНС по бухотчётности (если успеем скачать) | доходы юрлиц за год | `etl.raw_revenue` |
| Лист МОД2 | инвестпроекты (продукт 2) | сид → `etl.raw_invest` |

**Статус компании** (считает ETL):

| | `is_client` | `status` | Цвет на карте | По умолчанию |
| --- | --- | --- | --- | --- |
| Действующий клиент РТ — в кейсе и в действующем реестре | true | `active` | фиолетовый | показан |
| Потенциальный клиент — в реестре, нет в кейсе | false | `active` | оранжевый | показан |
| Клиент, исключённый из реестра — в кейсе, нет среди действующих | true | `excluded` | серый | скрыт |

«Исключён из реестра МСП» — не всегда «закрылся» (мог вырасти из МСП, не сдать отчётность). В интерфейсе так и пишем.

**Чего в данных нет и что делаем:**

- **Выручка.** Для юрлиц — из открытых данных ФНС, если удастся (`revenue_source = 'fns'`). Для остальных — модель
  (`revenue_source = 'model'`, `is_estimated = true`, бейдж «оценка»). Динамика — из двух лет ФНС или модель.
- **Точный адрес.** В реестре только район/город/населённый пункт → точка ставится рядом с центром населённого пункта.

Объём «не наших» — десятки–сотни тысяч строк (точно станет ясно после выгрузки). Поэтому **карта считается на сервере**
(кластеры по сетке), в браузер никогда не отдаём все точки сразу.

## Как устроена система

```
браузер ──► nginx :80 ──┬─ /api/auth/*            ► auth-service :8081 (Go)    ─► схема auth
                        ├─ /api/export/*          ► export-service :8082 (C#) ─► HTTP ► core-api /internal/*
                        ├─ /api/*                 ► core-api :8080 (Java)      ─► схема core
                        ├─ /internal/*            ► 404 (наружу закрыто)
                        └─ /                      ► статика фронта
ETL (Python, разовый): etl.raw_clients + etl.raw_rmsp (+ raw_revenue) ─► core.*
```

Правила БД, требования к сервисам и процедура сборки — в [README](../../README.md). Коротко: своя схема и свой
пользователь, к соседям — только HTTP, таблицы из кода не создавать, `Dockerfile` + `/health` + конфиг из env.

## Авторизация

- Все `/api/*`, кроме `POST /api/auth/login` и `POST /api/auth/2fa/verify`, требуют `Authorization: Bearer <accessToken>`.
- accessToken — JWT RS256 на 8 часов. Каждый сервис проверяет его сам по ключу из
  `GET http://auth-service:8081/internal/auth/jwks` (запрос при первом обращении, кэш 10 минут, при неизвестном `kid` —
  перезапросить один раз).
- Принимаем токен, только если подпись верна, `exp` не истёк, `iss = "radar-auth"`, в `amr` есть `"otp"`.

```json
{ "iss": "radar-auth", "sub": "1", "email": "demo@rt.ru", "name": "Демо Менеджер",
  "roles": ["manager"], "amr": ["pwd", "otp"], "iat": 1792780000, "exp": 1792808800, "jti": "…" }
```

- `/internal/*` требуют `X-Internal-Token: <INTERNAL_TOKEN>` (сравнение за постоянное время), JWT там не нужен.

## Формат

- JSON в camelCase, UTF-8. Даты — `"2022-07-10"`, моменты — ISO-8601 UTC. `null` для неизвестного, поле не пропускаем.
- Деньги — рубли (`revenueEst`), у инвестпроектов — млн руб. (`amountMln`).
- Множественный фильтр — повтором параметра: `?industry=trade&industry=logistics`.

**Ошибки** — во всех сервисах одинаково:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "revenueMin больше revenueMax", "details": { "field": "revenueMin" } } }
```

| HTTP | code | Когда |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | неверный параметр или тело |
| 401 | `UNAUTHORIZED` / `INVALID_CREDENTIALS` / `INVALID_CODE` | нет или плохой токен / пароль / код 2FA |
| 403 | `FORBIDDEN` | не хватает роли |
| 404 | `NOT_FOUND` | нет объекта |
| 409 | `CONFLICT`, `EMAIL_TAKEN` | конфликт |
| 413 | `TOO_LARGE` | выгрузка больше лимита |
| 429 | `TOO_MANY_ATTEMPTS` | 5 неверных кодов 2FA |
| 502 | `UPSTREAM_UNAVAILABLE` | сосед не ответил за 5 с |
| 500 | `INTERNAL_ERROR` | остальное (стектрейс — в лог) |

**Пагинация:** `?page=0&size=50` (size ≤ 200) → `{ "items": [...], "page": 0, "size": 50, "total": 123456 }`.
**Сортировка:** `?sort=revenueEst,desc`.

## `CompanyFilter` — общий фильтр компаний

Одинаково принимают `GET /api/companies`, `GET /api/map/cells`, `GET /api/export/companies`, `GET /internal/companies`.
Фронт хранит фильтр в URL и подставляет одну и ту же строку во все запросы.

| Параметр | Тип | Логика | Откуда требование |
| --- | --- | --- | --- |
| `client` | `all` (по умолчанию) / `ours` / `others` | все / только наши (`is_client`) / только не наши | куратор: три варианта |
| `status` | `active` (по умолчанию) / `excluded` / `all` | действующие в реестре / только исключённые из реестра / все | куратор: в файле есть закрывшиеся |
| `industry` | код, множественный | `industry IN (...)` | куратор: обязательно отрасль |
| `revenueMin`, `revenueMax` | руб/год | `revenue_est BETWEEN`; при заданной границе компании без выручки отсекаются | куратор: выручка «от … до» |
| `minLat`, `maxLat`, `minLon`, `maxLon` | градусы | видимая область карты: `lat BETWEEN … AND lon BETWEEN …` (все четыре или ни одного) | куратор: локация «как ПВЗ на карте» |
| `municipalityId` | int, множественный | район / город из списка | локация списком |
| `sizeCategory` | код, множественный | `size_category IN (...)` | |
| `growthMin` | % | `revenue_growth_est >= growthMin` | кейс: динамика роста |
| `isNew` | `true` | только «вновь созданные» | |
| `q` | строка ≥ 2 символов | `name ILIKE %q%` или `inn LIKE q%` | |

Все условия — через AND. Неизвестный код → 400.

## Демо-сценарий продукта 1 (по нему проверяем готовность)

1. Вход `demo@rt.ru` → код из аутентификатора → карта области: кластеры с долей наших/не наших.
2. Фильтр «Логистика», выручка от 10 до 100 млн → кластеры и список меняются вместе.
3. «Только не наши» → видно, где потенциальные клиенты; «Все» → видно распределение двумя цветами.
4. Приближаем Азов → кластеры распадаются на точки, список справа — только то, что в окне карты.
5. «Белые пятна» → подсвечены районы, в подсказке — почему.
6. «Показать исключённых» → серые точки; цифра «N из 759 клиентов исключены из реестра» — на слайд.
7. «В CRM» → скачался файл для Bitrix24 ровно с тем, что на экране.
8. Всё то же самое на телефоне.
